# Plan: Shared StatusTagComponent

## 1. Context

**Vấn đề:** Hiện tại logic hiển thị trạng thái bằng `nz-tag` (màu sắc, nhãn tiếng Việt) đang bị **trùng lặp** trên ít nhất 5 component khác nhau. Mỗi component tự định nghĩa `getStatusColor()` / `getStatusLabel()` / `getStatusText()` riêng, dẫn đến sự không nhất quán (cùng trạng thái `PENDING` nhưng màu sắc khác nhau) và khó bảo trì.

**Mục tiêu:** Tách logic hiển thị tag trạng thái thành một `StatusTagComponent` dùng chung, được lưu trong `shared/components/status-tag/`.

**Non-Goals:**
- Không thay đổi logic nghiệp vụ của bất kỳ component nào.
- Không thêm animation hoặc interactive behavior cho tag.
- Không tạo thêm API backend.

---

## 2. Constraints

- **Framework:** Angular 17+ Standalone Components
- **UI Library:** ng-zorro-antd (`nz-tag`)
- **Không thêm thư viện mới.**
- **Giới hạn kích thước:** Mỗi task tối đa 200 LOC.

---

## 3. Conventions

- Component mới phải là **Standalone**.
- Đặt tại: `src/app/shared/components/status-tag/`
- Tên selector: `app-status-tag`
- Đặt tên file: `status-tag.component.ts/.html/.css`
- Mỗi domain (Order, Quotation) có **config riêng** được truyền vào qua `Input`, không hardcode trong component.
- Không dùng `any` type — khai báo interface rõ ràng.
- CSS class trong shared component phải đặt prefix `st-` để tránh xung đột.

---

## 4. Contracts

### Interface `StatusConfig`
```typescript
export interface StatusConfig {
  color: string;   // Màu nz-tag: 'warning' | 'success' | 'error' | 'processing' | 'cyan' | 'orange' | 'blue' | 'green' | 'red' | 'default'
  label: string;   // Nhãn tiếng Việt
}

export type StatusMap = Record<string, StatusConfig>;
```

### `StatusTagComponent` Inputs
| Input | Type | Required | Mô tả |
|---|---|---|---|
| `status` | `string` | ✅ | Giá trị trạng thái từ backend (VD: `'PENDING'`) |
| `statusMap` | `StatusMap` | ✅ | Bảng ánh xạ status → { color, label } |
| `fallbackLabel` | `string` | ❌ | Nhãn mặc định nếu không tìm thấy trong map (default: hiển thị nguyên `status`) |

### Predefined Status Maps (constants)
```typescript
// src/app/shared/constants/status-maps.ts
```

## 5. Target Architecture

```
[Consumer Component HTML]
    ↓ [status]="order.status"
    ↓ [statusMap]="ORDER_STATUS_MAP"
[app-status-tag]
    → tìm entry trong StatusMap theo status key
    → render <nz-tag [nzColor]="entry.color">{{ entry.label }}</nz-tag>
```

**Lý do chọn `Input statusMap` thay vì hardcode domain:** Giúp `StatusTagComponent` hoàn toàn không biết domain nghiệp vụ, dễ mở rộng cho domain mới mà không cần sửa component.

## 8. Task Specifications

### Task 1 — Tạo `StatusTagComponent`

**Files:**
- `[CREATE] src/app/shared/components/status-tag/status-tag.component.ts`
- `[CREATE] src/app/shared/components/status-tag/status-tag.component.html`
- `[CREATE] src/app/shared/components/status-tag/status-tag.component.css`

**Responsibilities:**
- Nhận `status: string` và `statusMap: StatusMap` từ parent.
- Tra cứu entry trong map (case-insensitive).
- Render `<nz-tag>` với đúng màu và nhãn.
- Nếu không tìm thấy: hiển thị `fallbackLabel` hoặc nguyên `status`.

**Template (gợi ý):**
```html
<nz-tag [nzColor]="resolvedColor" class="st-tag">{{ resolvedLabel }}</nz-tag>
```

**Acceptance Criteria:**
- `status='PENDING'` + `ORDER_STATUS_MAP` → màu `warning`, nhãn `Đang xử lý`
- `status='UNKNOWN'` → hiển thị `UNKNOWN` (fallback)
- `status='pending'` (viết thường) → vẫn resolve đúng (case-insensitive)

## 9. Edge Cases

| Edge Case | Xử lý ở | Chi tiết |
|---|---|---|
| Status viết thường (`'pending'`) | Task 1 | Normalize về uppercase khi tra map |
| Status không tồn tại trong map | Task 1 | Hiển thị `fallbackLabel` hoặc nguyên `status` |
| `statusMap` là null/undefined | Task 1 | Guard check, render tag màu `default` |
| `support.component` có `getStatusLabel` cho steps | Task 4 | Giữ lại `getStatusLabel` cho `<nz-steps>`, chỉ migrate `nz-tag` |
| `admin-products` có nhiều loại tag | Task 5 | Chỉ migrate tag `isActive`, giữ nguyên category/stock tags |
